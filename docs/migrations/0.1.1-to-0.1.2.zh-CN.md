# 从 0.1.1 迁移到 0.1.2

`0.1.2` 是开发期 patch 发布，包含有意的破坏性调整，不提供运行时兼容别名。先运行离线检查；迁移诊断会定位源码文件和已删除的写法。

```bash
pnpm add -D @becomeopc/dshx@^0.1.2
pnpm exec dshx check
```

## 入口调整

| 0.1.1                                          | 0.1.2                                               |
| ---------------------------------------------- | --------------------------------------------------- |
| 从 `@becomeopc/dshx` 导入各类 authoring helper | 分别从 `/host`、`/client`、`/api`、`/settings` 导入 |
| `@becomeopc/dshx/conversation`                 | `@becomeopc/dshx/experimental/conversation`         |
| `@becomeopc/dshx/compiler`                     | `@becomeopc/dshx/tooling`                           |
| `@becomeopc/dshx/compat`                       | `@becomeopc/dshx/tooling`                           |
| `@becomeopc/dshx/cli`                          | `@becomeopc/dshx/tooling`                           |

根入口和 `/config` 现在只导出 `defineConfig` 与 `DshxConfig`。

## Host 与 Client 定义

Host 的 `api` 改为复数 `apis`：

```diff
 export default defineHost({
-  api: [statusApi.host(handlers)],
+  apis: [statusApi.host(handlers)],
 })
```

删除 Client 的 `api`/`apis`。最终产物中保留的 Hook 会在 tree-shaking 后自动推断能力：

```diff
 export default defineClient({
-  apis: [statusApi],
   slots: [statusSlot],
 })
```

Settings 只在 Host 声明所有权；不要给 Client 增加 Settings 列表。

## API Query

将 `useQuery` 改为 `useApiQuery`，并把 input 放入 options：

```diff
-const status = useQuery(statusApi, 'get')
-const refresh = useQuery(statusApi, 'refresh', { force: true }, { enabled })
+const status = useApiQuery(statusApi, 'get', { enabled: true })
+const refresh = useApiQuery(statusApi, 'refresh', {
+  input: { force: true },
+  enabled,
+})
```

用严格状态联合和 `refetch()` 替代 `{ loading, retry }`：

```tsx
if (query.status === "pending") return <p>{query.fetchStatus}</p>;
if (query.status === "error")
  return <button onClick={query.refetch}>{query.error.message}</button>;
return <p>{query.data.project}</p>;
```

命令式调用仍使用 `(input, options)`。无输入方法传 Signal 时写 `api.get(undefined, { signal })`，不要写 `api.get({ signal })`。

`ApiError` 不再公开构造器或 transport helper；使用 `isApiError(value)` 和只读字段。

## Standard Schema 方法

Schema 方法改用 `@standard-schema/spec@^1.1.0`，并推断四个阶段：

```ts
ApiMethodDefinition<ClientInput, HostInput, HostOutput, ClientOutput>;
```

input/output schema 只在 Host 执行一次。删除为旧行为补写的 Client 重复校验。`.host()` 必须实现所有方法且不能多出 handler。

## Settings Hook 返回值

删除以下字段：

```diff
-settings.base
-settings.user
-settings.mutation.error
-settings.mutation.clearError()
```

保留字段为 `status`、`value`、`revision`、`writable`、`mode`、`applies`、`secrets`、`error`、`mutation.pending`、`set` 和 `unset`。写入失败通过返回的 Promise reject；读取/同步失败位于 `settings.error`。

Client decoder 对无效数据必须抛错，返回 `undefined` 会被拒绝。secret 若可通过 union、intersection、transform 或不受支持的容器到达，即使存在 decoder 也会被拒绝；请将 secret 放到普通 object/dict/array 路径下。

## Slot 与 opaque contribution

将 `DshxSlotOptions` 改为 `SlotOptions`。不要检查、展开、序列化或手工构造 Slot、Prompt、API Host、Settings Host、Conversation contribution；`0.1.2` 按 helper 返回值身份验证 opaque contribution。

## Conversation 生命周期

将旧的 Conversation Node/Slot 分离写法和 `.component()`/`view` 改为纯生命周期加 `.render(Component)`：

```diff
-const reviewNode = defineConversationNode({
-  kind: 'review-job',
-  match(event) {},
-  start(context, match) {},
-  update(context, match) {},
-  buildViewNode(context) {},
-})
-const reviewView = defineSlot('conversation.chat.node', { ... })
+const reviewLifecycle = defineConversation({
+  kind: 'review-job',
+  events,
+  initial(context, event) {},
+  reduce(state, context, event) {},
+  project(state, context) {},
+})
+const review = reviewLifecycle.render(ReviewNode)

 export default defineClient({
-  slots: [reviewView],
+  conversations: [review],
 })
```

只有 renderer 可以调用 React Hook；生命周期回调必须保持纯函数。入口改为 `/experimental/conversation`，事件键只能来自官方 `SessionEventMap`。

## Config 与 Vite 插件

将 face 字符串改为对象：

```diff
 export default defineConfig({
-  host: 'src/host.ts',
-  client: 'src/client.tsx',
+  host: { entry: 'src/host.ts' },
+  client: { entry: 'src/client.tsx' },
 })
```

可选 Vite 插件放在对应 face 下；有状态 factory 必须分别调用：

```ts
export default defineConfig({
  host: { vite: { plugins: [hostPlugin()] } },
  client: { vite: { plugins: [clientPlugin()] } },
});
```

DSHX 不再抢占 `.css`。CSS Modules、PostCSS、Tailwind 和资源都走受约束的标准 Vite pipeline，请删除旧 CSS 字符串转换的 workaround。

## Programmatic build

将 `watch: true` 或旧 start 函数替换成明确 API：

```diff
-await buildClient({ ...options, watch: true })
+const watcher = await watchClient(options)
 watcher.on('event', event => { /* ... */ })
 await watcher.close()
```

`buildHost`/`buildClient` 返回 `BuildReport`；watch 函数返回 `BuildWatcher`，都不暴露裸 Vite 结果。

## 检查与验证

`dshx check` 现在完全离线，并包含 TypeScript `noEmit`。需要验证 Profile、Composition、bridge 和运行时 readiness 时显式执行：

```bash
pnpm exec dshx check
pnpm exec dshx check --runtime
pnpm exec dshx build
```

JSON 输出分别包含 `static`、`typecheck`、`runtime` 状态。`build` 在生成产物前运行类型检查。declarations 默认开启；确保 package.json 中所有 `exports`、`types` 和 `bin` 路径都有真实产物。
