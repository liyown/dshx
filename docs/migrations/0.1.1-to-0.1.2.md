# Migrate from 0.1.1 to 0.1.2

`0.1.2` is a development-line patch release with intentional breaking changes. It does not ship runtime aliases. Run the offline checker first; migration diagnostics point to the source file and removed construct.

```bash
pnpm add -D @becomeopc/dshx@^0.1.2
pnpm exec dshx check
```

## Imports

| 0.1.1                                    | 0.1.2                                                  |
| ---------------------------------------- | ------------------------------------------------------ |
| Authoring helpers from `@becomeopc/dshx` | Import from `/host`, `/client`, `/api`, or `/settings` |
| `@becomeopc/dshx/conversation`           | `@becomeopc/dshx/experimental/conversation`            |
| `@becomeopc/dshx/compiler`               | `@becomeopc/dshx/tooling`                              |
| `@becomeopc/dshx/compat`                 | `@becomeopc/dshx/tooling`                              |
| `@becomeopc/dshx/cli`                    | `@becomeopc/dshx/tooling`                              |

The root and `/config` entries now export only `defineConfig` and `DshxConfig`.

## Host and Client definitions

Rename Host `api` to the plural `apis`:

```diff
 export default defineHost({
-  api: [statusApi.host(handlers)],
+  apis: [statusApi.host(handlers)],
 })
```

Remove Client `api`/`apis`. Retained Hooks infer the capability after tree-shaking:

```diff
 export default defineClient({
-  apis: [statusApi],
   slots: [statusSlot],
 })
```

Settings remain a Host ownership declaration only; do not add a Client Settings list.

## API queries

Rename `useQuery` to `useApiQuery` and move input into the options object:

```diff
-const status = useQuery(statusApi, 'get')
-const refresh = useQuery(statusApi, 'refresh', { force: true }, { enabled })
+const status = useApiQuery(statusApi, 'get', { enabled: true })
+const refresh = useApiQuery(statusApi, 'refresh', {
+  input: { force: true },
+  enabled,
+})
```

Replace `{ loading, retry }` branching with the strict status union and `refetch()`:

```tsx
if (query.status === "pending") return <p>{query.fetchStatus}</p>;
if (query.status === "error")
  return <button onClick={query.refetch}>{query.error.message}</button>;
return <p>{query.data.project}</p>;
```

Imperative calls keep `(input, options)`. Use `api.get(undefined, { signal })`, not `api.get({ signal })`.

`ApiError` no longer has a public constructor or transport helpers. Use `isApiError(value)` and its read-only fields.

## Standard Schema API methods

Schema methods now use `@standard-schema/spec@^1.1.0` and infer four stages:

```ts
ApiMethodDefinition<ClientInput, HostInput, HostOutput, ClientOutput>;
```

Input and output schemas run once on the Host. Remove duplicate Client validation that was added only to compensate for the old behavior. `.host()` must implement every method and no extra keys.

## Settings Hook result

Remove these fields:

```diff
-settings.base
-settings.user
-settings.mutation.error
-settings.mutation.clearError()
```

The supported state is `status`, `value`, `revision`, `writable`, `mode`, `applies`, `secrets`, `error`, `mutation.pending`, `set`, and `unset`. Mutation failures reject the returned Promise; read/sync failures appear in `settings.error`.

Client decoders must throw on invalid data. Returning `undefined` is rejected. A secret reachable through a union, intersection, transform, or unsupported schema container is now rejected even if a decoder is present; move it under plain object/dict/array paths.

## Slot names and contribution opacity

Rename `DshxSlotOptions` to `SlotOptions`. Do not inspect, spread, serialize, or construct Slot, Prompt, API Host, Settings Host, or Conversation contributions. Recreate them with their public helper because `0.1.2` authenticates opaque contributions by identity.

## Conversation lifecycle

Replace the old Conversation Node/Slot pair and `.component()`/`view` forms with one pure lifecycle and `.render(Component)`:

```diff
-const reviewNode = defineConversationNode({
-  kind: 'review-job',
-  match(event) {},
-  start(context, match) {},
-  update(context, match) {},
-  buildViewNode(context) {},
-})
-const reviewView = defineSlot('conversation.chat.node', { ... })
+const reviewLifecycle = defineConversation({
+  kind: 'review-job',
+  events,
+  initial(context, event) {},
+  reduce(state, context, event) {},
+  project(state, context) {},
+})
+const review = reviewLifecycle.render(ReviewNode)

 export default defineClient({
-  slots: [reviewView],
+  conversations: [review],
 })
```

Only the renderer may use React Hooks. Lifecycle callbacks are pure. Import from `/experimental/conversation` and use only official `SessionEventMap` keys.

## Config and Vite plugins

Replace face strings with objects:

```diff
 export default defineConfig({
-  host: 'src/host.ts',
-  client: 'src/client.tsx',
+  host: { entry: 'src/host.ts' },
+  client: { entry: 'src/client.tsx' },
 })
```

Put optional Vite plugins under the face that uses them and call stateful factories separately:

```ts
export default defineConfig({
  host: { vite: { plugins: [hostPlugin()] } },
  client: { vite: { plugins: [clientPlugin()] } },
});
```

DSHX no longer intercepts `.css`. CSS Modules, PostCSS, Tailwind, and assets use the standard bounded Vite pipeline. Remove workarounds for the old CSS string transform.

## Programmatic builds

Replace `watch: true` or start-specific functions with explicit APIs:

```diff
-await buildClient({ ...options, watch: true })
+const watcher = await watchClient(options)
 watcher.on('event', event => { /* ... */ })
 await watcher.close()
```

`buildHost`/`buildClient` return `BuildReport`; watchers return `BuildWatcher`. Neither exposes a raw Vite result.

## Check and verification

`dshx check` is now fully offline and includes TypeScript `noEmit`. Use the runtime mode explicitly:

```bash
pnpm exec dshx check
pnpm exec dshx check --runtime
pnpm exec dshx build
```

JSON output reports separate `static`, `typecheck`, and `runtime` statuses. `build` runs type checking before producing artifacts. Declarations default to enabled; ensure package `exports`, `types`, and `bin` paths point to files that the build/pack actually creates.
