# 从 0.1 迁移到 0.2

`0.2.0` 将 DSHX 从 DSH `0.1.x` 契约代际迁移到 `0.2.x`。当前 adapter 为 `protocol-2`，真实运行时基线是源码 tag `dsh-v0.2.1-rc.2` 的构建。这是破坏性发布：`@deepseek-ai/dsh-client-runtime`、DSHX 旧 Settings provider，以及旧 Conversation/Connection 绑定都已删除，不提供运行时别名。

> npm 上的 `@deepseek-ai/dsh@0.2.1-rc.2` 产物目前包含过期的 profile-boot 代码。在上游重新发布前，请使用源码 tag 构建进行开发和冒烟。adapter 记录的验证来源是 `source`，因此 npm `0.2.1-rc.2` 按 experimental 处理。

## 1. 更新项目元数据

```json
{
  "devDependencies": {
    "@becomeopc/dshx": "^0.2.0",
    "@deepseek-ai/dsh": "0.2.1-rc.2"
  },
  "peerDependencies": {
    "@deepseek-ai/dsh": ">=0.2.1-rc.2 <0.3.0-0"
  },
  "engines": {
    "dsh": ">=0.2.1-rc.2 <0.3.0-0"
  }
}
```

公开支持范围优先写入 `engines.dsh`，`peerDependencies["@deepseek-ai/dsh"]` 作为回退；本地开发保留一个具体 `devDependencies` 版本。

从依赖、peer 和 `dsh.client.inject` 中移除 `@deepseek-ai/dsh-client-runtime`。DSH 0.2 不再发布该包，Slot、store、Settings、Session 和 Conversation 服务分别来自对应的细粒度包。

## 2. Settings 改为插件 Config

`defineSettings()` 仍声明一个 Schemastery schema，但现在它是 DSH 投影到 Settings 表单的插件 `Config`。不再有 namespace 字段，也不再有 Host 注册调用。

```ts
// src/settings.ts（Host 与 Client 共享）
import Schema from "@deepseek-ai/schemastery";
import { defineSettings } from "@becomeopc/dshx/settings";

export const runtimeSettings = defineSettings({
  schema: Schema.object({
    showActivity: Schema.boolean().default(true),
    threshold: Schema.number().default(3).min(0).max(10),
    token: Schema.string().role("secret"),
  }),
});
```

```ts
// src/host.ts
import { defineHost } from "@becomeopc/dshx/host";
import { runtimeSettings } from "./settings.js";

export default defineHost({
  config: runtimeSettings,
  setup(ctx, config) {
    const value = config?.get(); // 稳定引用，实时编辑会原地更新
  },
});
```

```ts
// src/client.tsx
import { useSettings } from "@becomeopc/dshx/client";
import { runtimeSettings } from "./settings.js";

const state = useSettings(runtimeSettings);
```

变化要点：

- **`defineHost` 不再接受 `settings` 数组。** 只接受一个可选 `config`。
- **没有 `settingsNamespace`。** DSH 用加载插件的 Host profile entry id 标识表单；DSHX 将该 id 写入 Client 产物，因此插件必须通过它 bundle patch 中声明的 entry 加载。
- **没有 Host `ctx.settings.register` / `SettingsProvider`。** DSH 通过 `SettingsForms` 拥有表单，Client 读取 `ctx.configForms.get(entryId)`。
- **根 schema 自动 volatile。** DSHX 对根 schema 调用 `.volatile()`，让所有字段实时生效；不要再给单个字段加 `.volatile()`，否则 `defineSettings()` 会抛错。
- **`set`/`unset` 返回 `boolean`。** 需要有序编辑或 revision fence 时使用 `mutate(ops, expectedRevision)`。
- **secret 在传输中脱敏。** `state.secrets` 只报告 schema 声明的路径以及是否已设置，值不会到达 Client。

当 `useSettings` 在 tree-shaking 后保留时，Client 仍需在 `dsh.client.inject` 中声明 `@deepseek-ai/dsh-client-ui-settings`。能力名从 `client:settings-scope` 改为 `client:config-forms`。

## 3. Conversation 使用 `uiConversation`

`defineConversation()` 的生命周期形状不变，但注册入口改为官方 Client 服务：

```ts
// 0.1
ctx.conversationEvents.register(definition);

// 0.2
ctx.uiConversation.events.register(definition);
```

renderer 类型改从 `@deepseek-ai/dsh-client-ui-conversation/client` 导入。从 `dsh.client.inject` 移除 `@deepseek-ai/dsh-client-runtime`；如果贡献组件，保留官方 conversation renderer 包。存在 definition 时 DSHX 会自动加入 `uiConversation` inject，`dshx check` 会报告缺失的包边。

自定义 durable event 类型仍不受支持。Session 格式为 `4`，只接受官方 `SessionEventMap` 键；`command/run`、`command/done` 等命名键在冒烟场景中仍可用。

## 4. Connection、RPC 与 API Hooks

Host 注册改为 peer 路由：

```ts
// 0.1
connection.rpc.handle(channel, handler, { authority: "loopback" });

// 0.2
connection.rpc.handle(channel, handler);
```

handler 会收到官方 `peer` 事实。Client 不再调用 `connection.api`；生成的 Remote namespace 通过 `ctx.remote.<namespace>` 使用，事件使用 `$on`/`$stream`。DSHX 的 `useApiQuery` 与命令式 API 绑定保持作者侧形状，但能力名现在是 `connection:peer-admission`。DSHX 的线路径与 envelope 不变：顶层 `/dshx-<hash>/<method>` channel，方法名在 DSHX envelope 内。

DSH 0.2 要求浏览器认证：DSH 发 launch token，浏览器先访问 `/connect?token=…` 换取签名 cookie，再调用 `/api/...`。仅靠 loopback 的裸请求会失败。这影响自定义冒烟脚本，不影响 DSHX 自己的 Client runtime。

## 5. Prompt、Commands 与 Tools

- Prompt assembly 改为 `personaPrefix`/`personaSuffix`，由 DSH 统一分配顺序。DSHX 保留 `definePromptSection`/`definePromptContext` 与 `order` 字段，但将 order 视为提示。
- Command input 使用 `attachments` 取代 `images`；`CommandResult` 可能带 `sourceEventSeq`。
- Tool 不再支持 `mode: 'both'`；native 与 PTC 分别声明。
- `ctx.codeRuntime` 改为 `ctx.ptcRuntime`；`CallId` 改为 `ToolCallId`；`JsonValue` 来自 `@deepseek-ai/dsh-util-values`。
- DSHX 原样 re-export 官方 `defineTool`，这些类型随官方包一起更新。

## 6. Manifest 与 bundle patch

- 接受 `manifestVersion: 1`。
- `dsh.bundle.patch` 可以是字符串或路径数组；DSHX 会扫描每个 patch 来解析 Settings entry id。
- `/invariant` 子路径已删除；从包根、`/host`、`/client`、`/api`、`/settings`、`/experimental/conversation` 或 `/tooling` 导入。
- `create-dshx` 会写入 `engines.dsh`；`dshx check` 报告缺失或过期的声明。

## 7. Inspect 与 `add ui`

DSH 0.2 没有一方运行时 Slot catalog。DSHX 行为：

| 命令                                | 0.2 行为                                                                         |
| ----------------------------------- | -------------------------------------------------------------------------------- |
| `dshx inspect tools`                | 通过 Host bridge 读取运行时数据                                                  |
| `dshx inspect services`             | 同上                                                                             |
| `dshx inspect events`               | 同上                                                                             |
| `dshx inspect configs`              | 同上                                                                             |
| `dshx inspect slots`                | 返回 `DSHX3204`；Slot 是编译期契约                                               |
| `dshx add ui --slot X --provider Y` | 使用显式值生成，并给出 `DSHX6112` 警告，因为无法用 provider catalog 校验注册形状 |

`dshx add ui` 仍会校验 provider 类型入口、Client entry、文件位置和生成后的 manifest。list Slot 请传 `--id`/`--order`；生成文件由 `dshx check`/`build` 按 provider 类型检查。

Host bridge 仍由 DSHX 自己维护并限定在 composition scope 内，不使用开发检出中的 7 个本地 DSH `inspect-bridge` 提交。

## 8. 验证清单

```bash
pnpm install
pnpm --filter @becomeopc/dshx test
pnpm check:all
pnpm smoke:dsh -- --dsh-source /path/to/deepseek-harness
```

不带 `--dsh-source` 的 `pnpm smoke:dsh` 使用 npm 产物，只适合诊断上游发布漂移。0.2 源码冒烟覆盖 Host-only 与 Client-only 项目、完整 Host/Client 启动、Settings 写入与 revision fence、API 调用、Commands、Prompt contribution、Conversation replay、HMR、Host restart，以及 tools/services/events/configs 的运行时 Inspect。
